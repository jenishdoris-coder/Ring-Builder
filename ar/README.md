# Integrated ring try-on

The main builder opens `src/ARExperience.tsx` as a lazy React camera view, directly from its viewer toolbar. It receives the selected head, band, scales, metal colors and engraving as props. It has no separate web server, iframe or model-selection URL. The studio pauses rendering while AR is open and resumes its existing view on return. Closing, leaving the page or hiding the tab releases camera tracking.

Run `npm ci` from the repository root to install the workspace. `npm run dev` serves everything on port 5173. `npm run dev:secure` serves port 5443 with local `.cert/server.crt.pem` and `.cert/server.key.pem`; local certificates are ignored by Git and Vercel. Phone cameras require HTTPS. Production uses the site's normal HTTPS origin.

`npm run build` includes the MediaPipe model/WASM, OpenCV and Draco files from `runtime/` under `/ar/runtime/`. They are fetched only when try-on needs them. Jewelry and lighting use the existing catalog and Cloudflare asset addresses. The UI never uploads camera frames; Save photo downloads a local PNG. Existing admin and pricing APIs are unchanged.

Rendering retains the actual WebGI DiamondPlugin and orthographic ray correction. The cropped jewelry canvas is supersampled above native pixel density where possible, with a one-million-pixel budget and texture-size limit. No temporal history is used, so hand depth and moving jewelry stay in the same frame. Pixel-budget limits can reduce supersampling on unusually large crops.

The integrated v9 compositor matches the original try-on's weighted 3×3 hand-edge feathering, depth transition and smooth rear-band fade. It reconstructs jewelry world positions from the current WebGI camera and depth buffer, so the fade follows the fitted finger axis. Feathering compensates for supersampling to retain its screen-space softness. Hand-guide controls and guide drawing are removed, including photo overlays. Development replay includes a GPU fade comparison alongside its existing projection and occlusion checks.

V10 finger attachment: texture tracking reads a stable crop around the proximal finger directly from the captured full-resolution camera frame into a bounded 256×256 image. The window stays fixed through landmark jitter, preserving stationary-image evidence; adjacent-frame flow is converted through each frame's own crop before it reaches screen-space pose filtering. LK rejection can fall back to smaller skin patches. A missing detection hides stale jewelry after 55 ms while retaining the stabilized attachment for up to 300 ms; distant reappearances and actual hand changes still seed a fresh pose. Reacquisition does not spend the missed interval chasing a noisy new joint position. The original edge fade and WebGI diamond rendering are retained.

V10 validation: all 126 AR regressions passed, including real patch matching across a moving camera crop, stationary crop retention, coordinate conversion and short detector-loss recovery. The main TypeScript check passed. These synthetic and recorded regressions establish filter behavior, not physical hand fit on every device.

V11 neighboring-hand occlusion: palm and neighboring finger masks retain their observed camera XY while only depth is reconciled to the stabilized ring frame. Independent chain filtering suppresses alternating noise and follows consistent small crossings without the old 6–10px release jump. The palm mesh includes wrist width and finger-web coverage; rounded internal finger joints close bent-cylinder gaps without extending past fingertips. A held ring pose retains its matching hand mask through a brief missed detection. Fixed-reference patch tracking now supplies ring transport first, with LK as recovery when patch matching cannot follow an appearance change.

V11 validation: all 130 AR regressions and the main TypeScript check passed. Tests cover camera-space mask alignment, slow neighboring crossings, static jitter, depth-only crossings, wrist coverage, bent-joint coverage and the recorded fist's raised setting. Camera-free WebGI replay of the recorded bent hand also passed the front/behind occlusion check; 59,579 of 91,057 unmasked jewelry pixels remained visible with the hand mask applied. Live hand overlap still needs device validation.

V12 turn tracking uses a short elapsed-time history, coherent rotation and independently changing projected palm/finger shape to confirm out-of-plane motion when skin matches drop out. Verified stationary pixels still veto inferred rotation. The previous .92 finger-depth clamp (about 67°) now allows .985 (about 80°), and a recently observed turn settles through a smaller angular deadband. Synthetic slow-turn tests at 16, 33 and 100 ms frame intervals reduced worst turn lag from approximately .293 to .026 radians while retaining stationary-hand regressions.

V12 shadows use the same oval cross-section as the finger depth proxy, with a small offset, lower opacity and reduced shadow bias. The old kernel patch targeted another Three version and never modified the pinned r160 shader. The receiver now uses bilinearly interpolated comparisons under a weighted tent, with the same 512×512 map. Hand clipping preserves the shadow material's own program cache key. Native camera-free checks measured 46 alpha levels at 18% maximum opacity in front view and 39 levels at 15% in a pitched view. All 134 AR regressions, TypeScript and the production build passed. Physical hand fit and real-camera lighting still require device validation.
